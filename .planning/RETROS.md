# RETROS — process reviews during backlog runs

A short review after every 3-5 merged changes of a shipyard backlog run: what worked, what did not,
and what changes in the `ship` skill before the next batch. The "change" items become a `ship` PR
that merges before the next batch launches, so the next children run on the corrected skill.

## Retro 1 — 2026-09-28, after #261 #264 #263 #262 #266

Batch: 5 PRs, 12 issues closed (plus 2 superseded ones closed with evidence), open count 79 → 66.
Open-to-merge time 6-18 min per PR, except #262 (527 min — its slot was dead for most of it).

### Went well

* **Clusters.** One PR closing 2-4 related issues cost about what a single-issue PR did; the review
  battery stayed proportionate (#264, docs-only, cleared in one round).
* **Inflow held.** Standing orders to comment onto an existing issue rather than file kept new
  issues near zero across the batch.
* **Reviews caught real defects before merge:** a security finding in the new close-sweep text
  (#261), a `root=` value cut at a space before `rm -rf` (#266).

### Went badly

* **A ported test SIGKILLed the owner's whole session, four times.** A child copied a test from a
  stale unmerged branch and ran it; `pgrep -P` with no pattern lists every process on macOS and the
  test fed that to `kill -9`. Each resume of the slot re-ran the interrupted test. Nothing in the
  skill made the child read the destructive paths of code it had not written, and nothing made a
  resumed session ask whether its last command caused the crash it was resuming from (#265).
* **Findings were silently lost.** The documented intake reads an issue's body, not its comments,
  so scenarios added by the filing ladder's rung 2 were invisible to whoever later closed the issue;
  and non-blocking review findings stayed on merged PRs — a harvest found 36 never fixed and never
  homed (#268).
* **The close sweep was sized by area, not by diff.** A docs-only PR re-checked 69 open issues.
* **Launch text with newlines** produced a slot name that ran as shell commands (#198).
* **The supervisor ran three slots** when the owner's limit was two, and resumed slots without first
  asking why they died.

### Change in `ship` (next PR, before batch 2)

1. Intake reads every issue **with its comments**; each comment scenario is in scope or explicitly
   re-homed; `Closes #N` only when all of #N's comments are addressed (#268).
2. At hand-off every unfixed non-blocking finding goes onto an open issue by the filing ladder, and
   the PR record says where (#268).
3. The close sweep checks only open issues whose named files the diff touches.
4. **Code you did not write** — ported from another branch, pasted from an issue, generated by a
   tool — gets its kill / `rm -rf` / signal paths read before it runs; a helper that signals a list
   of pids refuses pid ≤ 1 and bounds the list; `pgrep -P` never without a pattern.
5. **On resume after a crash**, do not re-run the interrupted command until you have checked whether
   it caused the crash (the system log names a signal's sender).
